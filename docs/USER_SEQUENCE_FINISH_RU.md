# Доведение пользовательской вертикальной последовательности

Предпочтительный способ принятия решений теперь описан в
[CREATIVE_FINISH_RU.md](CREATIVE_FINISH_RU.md): совместное планирование Motion,
переходов и цвета по соседним сценам, затем проверка всего фильма. Это также
маршрут для новой структуры, созданной с нуля. Аудио не участвует в этом review;
существующий preparer ниже сохраняет аудио исходного пользовательского проекта.

Обновлено для версии 2026.10.03.01. Вход — сохранённый проект Premiere и уже
собранная пользователем вертикальная последовательность. Пользователь определяет
содержание, порядок и длительности. Этот маршрут не требует повторно проходить
INGEST → WIDE → FULL и не подменяет пользовательский монтаж автоматическим.

## Сохраняемый рабочий метод

1. Прочитать фактический `.prproj`, все видео/аудиодорожки, исходники, IN/OUT,
   длительность, Motion, Lumetri, существующие переходы и плагины. Сохранить
   snapshot и SHA-256 проекта. Проверить исходники; старый отчёт не заменяет чтение.
2. Из исходников составить контактные листы и оценить каждый кадр: положение лиц,
   нескольких участников, текст, горизонтальные сцены внутри вертикального монтажа,
   ART и уже анимированные вставки. Preview из исходников не воспроизводит плагины.
3. Согласовать индивидуальные Scale/Position и движение. Не применять общий crop
   ко всем сценам. Для участников по краям оставлять поля; короткие вставки и ART
   с собственным движением могут остаться без дополнительной анимации. Мягкий
   импульс задавать по длительности и содержанию, сохраняя редактируемые ключи.
   Маркеры пиков полезны для будущей музыки; без музыки нельзя заявлять BPM-синхронизацию.
4. Добавлять переходы выборочно, проверяя handles, соседние клипы и отсутствие
   наложений. Сохранять прямые склейки в действии. Исходные переходы не удалять.
   Цвет оценивать по сценам; сохранять нативный Lumetri и существующие плагины.
5. Подготовить отдельный WORK-проект, новую sequence, JSON, JSX, резервную копию и
   журнал. Пользователь открывает WORK и запускает JSX через Run Transition Script.
   Передать полный путь к JSX отдельным копируемым блоком. Adobe автоматически
   не запускается; подготовленный пакет получает `USER_ACTION_REQUIRED`.
6. Проверить реальные native logs, сохранённый проект, неизменность исходных
   последовательностей, тайминг, звук, кадрирование, Motion, цвет и переходы.
   После сбоя использовать новый пакет, не наслаивать эффекты повторным запуском.
   Нативный preview/export выполнять только по текущему заданию. Редактируемый
   проект может быть самостоятельным результатом. До проверки итог — QA_PENDING.

## Переиспользуемая подготовка

`scripts/prepare_user_sequence_finish.py` и `config_user_sequence_finish.example.json`
выделяют Motion/переходы последнего вертикального прохода в конфигурируемую процедуру.
Индивидуальные решения и исторические исполнители находятся в архиве задачи.
Новый шаблон прошёл offline проверки; его обобщённая версия требует собственного
нативного open-check/readback при первом применении. Исторический результат не
является QA новой версии.

```powershell
python scripts/prepare_user_sequence_finish.py --config <LOCAL_PATH>
python scripts/prepare_user_sequence_finish.py --config <LOCAL_PATH> --prepare
```

Первая команда — read-only dry-run; вторая создаёт пакет и копию. Поддерживаемый
контракт сейчас — 2160×3840, 25 fps, выбранная видеодорожка. `edits`: список
`{"index": 1, "scale": 100, "position": [0.5, 0.5], "keys": []}`;
индексы клипов начинаются с 1 на выбранной дорожке. Ключ: `[кадр, Scale, [X,Y]]`.
`transitions`: `{"incoming": 2, "cut": 125, "frames": 10}`; `cut` — реальная
граница входящего клипа в кадрах sequence. Alignment 0.5 — центрированный,
0 — начинается на склейке. Native readback дополнительно проверяет результат QE.
Самостоятельно выставленные Scale/Position требуют визуального review.

Шаблон сохраняет существующий Lumetri, звук и монтаж; новые цветовые поправки
не применяет. Для отдельных цветовых планов сохранены общие исполнители
`tools/prepare_plan_color.py` и `tools/prepare_native_finish.py`; перед применением
нужно подготовить соответствующий им план, а не добавлять `colors` в этот конфиг.
`export_preview` по умолчанию false; для экспорта нужны true и существующий `.epr`.

## Будущее горизонтальное расширение

Входом также может стать пользовательский горизонтальный монтаж без Motion,
переходов и цветокоррекции. Содержание и структура уже заданы пользователем;
доведение добавляет выразительность без пересборки сюжета. Перед поддержкой 16:9
нужно отдельно проверить геометрию, ключи, handles, экспортные presets и native QA.
Текущий вертикальный preparer отклоняет 16:9; готовая поддержка не заявляется.
