# Постоянное хранение family task

## Разделение TASK, output и Video Project — 2026-10-03

Для новых задач рекомендуется `task_root`: внешний каталог полного жизненного
цикла героя/года (например, `Hero/2027/TASK`). `output` внутри него — результаты,
а `config`, `inputs`, `classification`, `plans`, `logs`, `recovery` — данные для
повторного запуска. Имя папки TASK само по себе не меняет контракт старых скриптов.
Существующий family pipeline пока использует `final_output_dir` и
`classify.permanent_project_dir`; переименовывать старый output без миграции
конфигураций и ссылок Premiere нельзя. Новый user-sequence preparer принимает
`task_root` явно. Его `premiere_project_dir` должен быть отдельным каталогом.

В настроенном Video Project хранятся `.prproj`, autosave/backup, JSX и `.epr`.
Фото, ART, генерации, конфигурации, решения, классификации и история — в каталоге
данных героя. JSX допустимо дублировать в recovery как точный снимок исполнения.
Файлы тестовых запусков/кэша не заменяют эти данные. Исходный код тестов остаётся
частью процедурной проверки; удаляются их временные результаты.

Процедура переноса — `tools/archive_family_workspace.py`: внешний конфиг по
`config_workspace_archive.example.json`, `plan` → `archive` → проверка списка →
`apply`. Все копии проверяются SHA-256 до первого удаления. Старые рабочие
каталоги заменяются junction; при очистке их нельзя обходить рекурсивно.
В manifest сохраняются источник, постоянный путь, размер и hash каждого файла.
Архив исторического скрипта не означает, что его старые пути готовы к запуску:
при восстановлении нужна карта путей и актуальная версия процедур.

Ветка пользовательского монтажа описана в
[USER_SEQUENCE_FINISH_RU.md](USER_SEQUENCE_FINISH_RU.md).

## Совместимый контракт существующих задач

`final_output_dir` из конфигурации героя — канонический каталог результатов.
`classify.permanent_project_dir` должен указывать на тот же каталог.

Внутри него сохраняются ART, классификация, manifests, планы, отчёты, JSX,
review, проекты (`projects`), конфигурация (`config`) и полное рабочее состояние
(`tasks/<TASK>`). В репозитории `tasks/<TASK>` может быть только junction на это
состояние. `family_contract.task_path` проверяет целевой каталог по task config.

При подготовке новых задач сразу создавать данные в каталоге героя. Не создавать
отдельное основное хранилище в FamilyMemoryHub и не складывать массивы данных
героев в репозитории. Небольшая конфигурация в репозитории допустима как точка
входа; каноническая копия конфигурации должна быть в каталоге героя.

При включённом `retain_family_results` pipeline дополнительно сохраняет в
`RECOVERY` проверенные архивы рабочего состояния, конфигурации, сохранённых
проектов и кода восстановления. Оригинальные фото/видео — отдельные входные
данные, которые также необходимо сохранять. Сохранение архивов не подтверждает
нативную проверку Premiere и не включает несохранённые изменения приложения.

При миграции сохранять checksums и старые адреса через совместимые ссылки, пока
исторические проекты и manifests используют эти адреса. Потеря репозитория не
должна означать потерю данных героя: восстановление выполняется из каталога героя
и его RECOVERY. Удаление содержимого через junction удаляет реальные данные;
очистка репозитория не должна обходить такие ссылки рекурсивно.
