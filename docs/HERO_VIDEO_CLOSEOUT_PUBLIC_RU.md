# Архивирование завершённого видеозадания

`tools/hero_video_closeout.py` переносит полезные данные из `output/TASKnnn` в постоянные каталоги героя, проверяет копии и удаляет только явно запланированные файлы. Python 3.11+, стандартная библиотека; AI и Premiere для этой операции не запускаются.

## Конфигурация

Создайте личный `config_Hero.local.json` с абсолютными путями `source_materials_dir`, `premiere_project_dir`, `project_video_exports_dir`, `regeneration_assets_dir`. Скопируйте `config_closeout.example.json` в `config_closeout_TASK999.local.json`, укажите ID задания, путь к конфигу героя, корни проверки ссылок и точные имена принятых проекта и видео.

Реальные конфиги, отчёты и медиа не входят в публичную поставку. Шаблон требует заполнения; пути `<LOCAL_PATH>` нужно заменить локальными каталогами. Все команды выполняются из папки `source/` публичного пакета либо из корня исходного проекта.

```bat
run_hero_video_closeout.bat plan "config_closeout_TASK999.local.json" "cleanup_archive/TASK999/plan.json"
run_hero_video_closeout.bat archive "config_closeout_TASK999.local.json" "cleanup_archive/TASK999/plan.json"
run_hero_video_closeout.bat verify "config_closeout_TASK999.local.json" "cleanup_archive/TASK999/plan.json"
run_hero_video_closeout.bat cleanup "config_closeout_TASK999.local.json" "cleanup_archive/TASK999/plan.json"
```

Последняя команда показывает кандидатов, не удаляя их. Для удаления проверенных копий добавьте `--apply`. Затем `publish-report` с теми же путями сохранит журнал в постоянной папке героя.

## Что защищено

- Копии проверяются по SHA-256. Изменение исходника, конфигурации или финального результата останавливает очистку.
- Файлы, на которые ссылаются сохраняемые Premiere-проекты, остаются на месте. Укажите в конфигурации все каталоги с такими проектами.
- В архивных копиях `.prproj` меняются только пути. Оригинальные байты изменённых файлов сохраняются отдельно; эффекты и монтаж проверяются обратным чтением XML.
- Исходный фотоархив и текущие финалы не удаляются. Область удаления ограничена папкой задания в `output`; junction и symlink запрещены.
- История удалений сохраняется при повторном запуске. Конфликты назначения не перезаписываются.

Структурная проверка не заменяет нативный open-check Adobe. При повторном использовании исторического проекта проверьте его в Premiere. Исторические ссылки, уже не разрешавшиеся до переноса, перечисляются в отчёте.

## Если материал перенесён вручную

Перенос папки не обновляет ссылки в `.prproj`. `tools/hero_workspace_finalize.py` предназначен для отдельного, явно настроенного завершения: сравнивает хеши перенесённых медиа со старым планом, готовит план исправления ссылок, архивирует перечисленные устаревшие утилиты и только затем удаляет их рабочие копии. Конфигурация содержит точный список файлов; универсального «удалить всё старое» нет. Перед применением исправления ссылок на месте Premiere должен быть закрыт. Текущие принятые результаты проверяются на неизменность.

Альтернативный маршрут `--stage` подготавливает проверенный ZIP и новые проекты с суффиксом `_RELINKED` локально. После отдельного копирования ZIP и новых проектов в назначения из `staged_copies.json`, команда `--prune-staged` проверяет постоянные копии и удаляет только перечисленные устаревшие файлы рабочего репозитория. Старые проекты при этом не перезаписываются; для продолжения работы используется версия `_RELINKED`.

## Подготовка к публикации

Используйте `run_prepare_public_bundle.bat <новая-папка-пакета>` для сборки отдельной публичной версии. Batch отказывается писать в существующую папку, чтобы ранее исключённые приватные файлы не остались от старой сборки. Прямой вызов для новой папки: `main_project_publication.py --target-dir <папка-пакета>`. Не отправляйте рабочий каталог с семейными задачами и его Git-историю в публичный репозиторий. Удаление файла или запись в `.gitignore` не удаляет его из старых коммитов.

Публикуются общий код, обезличенные примеры и документация. Личные конфиги, приватные отчёты, медиа и браузерные профили остаются локально. Пакет необходимо проверить до отдельного commit/push; сама сборка не отправляет данные на GitHub.

Batch автоматически запускает `tools/audit_public_bundle.py`: сверка файлов с манифестом, запрещённых типов и конфигов, стандартных шаблонов секретов, синтаксиса Python и JSON. Для повторной проверки: `python -B tools/audit_public_bundle.py <папка-пакета>`. Через `--private-term` можно дополнительно проверять отсутствие конкретных личных имён или идентификаторов; результат не печатает найденные секретные значения.

## Очистка временных данных

После завершения проверок выполните dry-run:

```bat
python -B main_cleanup_artifacts.py --include-test-runtime-items
```

Просмотрите JSON/TXT-отчёт и повторите команду с `--execute`. Не включайте массовую очистку `output` для удаления остатков одного задания. Временные сборки `tmp_release_*`, тестовые папки и staging-копии проверяются отдельно: путь внутри рабочего каталога, отсутствие ссылок/junction, отсутствие нужных исходников. Staging ZIP и `_RELINKED` копии удаляются только после совпадения SHA-256 с постоянными назначениями. Сохраняйте журналы, постоянные архивы, конфиги и текущий публичный пакет; браузерный профиль содержит сессию входа и не является обычным временным файлом.

## Статус AI

План общей производственной цепочки предусматривает AI по умолчанию для анализа изображений, классификации и структуры видео, с отключением целиком или по стадиям и повторным использованием кэша. Это проектируемый интерфейс; команды closeout уже реализованы и AI не вызывают. Качество итогового видео зависит также от исходников, монтажа и проверки результата.
