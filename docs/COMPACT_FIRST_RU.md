# Первая сборка после CLASSIFY — сразу компактная

Основание: BASE_COMPACT_1.txt и уточнение пользователя от 21 сентября 2026. Принцип действует для общей технологии, включая первую FULL и последующую MINIMAL. Типичные 3–5 и 1–2 минуты соответственно — ориентиры; особый длинный фильм требует явного задания. Нельзя сначала сохранять избыточность, чтобы потом обязательно её удалять.

## Выбор длительности

Для каждого выбранного видео, фото или ART монтажное обоснование отвечает: что зритель должен понять; когда этого уже достаточно; добавляет ли дальнейшее время новую информацию, эмоцию или художественно необходимую паузу. Убирается время внутри содержания, а не механически одинаковая доля каждого элемента. Взгляд, реакция, жест, портрет и художественная работа могут требовать разной длительности.

Неизвестные границы отмечаются СПОРНО. Классификация по отдельным кадрам не доказывает точный момент завершения действия. Визуальный анализ и проверка входов/выходов остаются частью редакторской работы, до утверждения монтажа.

## Что делают скрипты

- `tools/build_video_structure.py`: по умолчанию `duration_mode: compact`. Целевая длительность — верхний бюджет планирования с прежним допуском 10%, без нижнего порога. Например, содержательный план 264 с при ориентире 300 с принимается без добавления секунд. Превышение бюджета возвращается на содержательную редакцию; автоматического уменьшения нет.
- Для каждого элемента модель получает требование обосновать достаточность длительности в `reason`, сохранить работающие паузы и явно указать сомнения. Проверка чисел не доказывает художественную достаточность.
- `duration_mode: target` оставлен для явно заданного хронометража с допуском ±10%. Несоответствие — ошибка для редакции; фотографии всё равно не растягиваются автоматически. `coverage` сохраняет широкое покрытие граней героя без общего лимита, но с тем же принципом достаточного времени внутри каждого элемента.
- `tools/run_hero_pipeline.py` передаёт режим в этап структуры. Новые примеры pipeline, структуры и альтернатив используют `compact` явно.
- `tools/review_draft_alternative.py` применяет тот же принцип при итерациях. Пропорциональная балансировка и автоматическое удаление сцен с конца ради жёсткого лимита отключены. Превышение требует редакторского изменения, а не произвольной потери содержания.
- `tools/render_structure_draft.py` сохраняет объяснение выбора в монтажном плане и отмечает проверку тайминга как ожидающую. Рендер не подгоняет длительности.

## Что ещё требует просмотра

Генератор структуры опирается на существующую классификацию. Он не стал анализатором непрерывного видео. Автоматический черновой выбор исходного диапазона по-прежнему использует начало первого достаточно длинного размещения. Такие In/Out не считаются проверенными по смыслу: их нужно оценить по доступному видео и при необходимости исправить конкретным монтажным планом. Общий компактный хронометраж не заменяет эту проверку.

FULL проходит просмотр, редакции и LOCK; затем MINIMAL получает собственные редакторские решения и приёмку. Принцип не означает одновременный автоматический экспорт обеих версий. Старые принятые результаты, личные конфигурации героев и существующие Premiere-проекты автоматически не пересобираются. Существующие checkpoint продолжают обозначать ранее выполненные этапы; новый пересмотр первой сборки оформляется отдельным запуском, без переписывания истории.

## Проверки реализации

Тесты проверяют отсутствие дописывания секунд и процентной подгонки, неизменность плана при превышении лимита, сохранение финальных сцен, ограничения исходного видео, уникальность ID, обязательные элементы и продолжение workflow. Реальные API-запросы, рендеры и Premiere при проверке этих изменений не запускаются.
