# Универсальная очередь изображений → видео

Это необязательная художественная ветка рядом с основной технологией монтажа.
Пользователь вручную отбирает фотографии или художественные изображения и
помещает их в `input`. Автоматический отбор и наполнение `input` из классификации
пока не реализованы. Готовые видео, акварели и двойные экспозиции можно использовать
при ручном монтаже отдельного художественного фильма; вставка в MAIN/SHORT
и сборка такого фильма не выполняются этим BAT автоматически.

Для публичной установки скопируйте `config_grok_queue.example.json` в
`config_grok_queue.json`, заполните героев/цель и настройте пути в отдельной
копии `config_grok_delivery.example.json`. Укажите эту копию в `delivery_config`.
Шаблон использует ID `PROJECT`; команда — `run_grok_queue.bat PROJECT`.
Личные конфиги и фотографии не поставляются в GitHub-пакете.

Из корня проекта:

```bat
run_grok_queue.bat BM26
```

Без аргументов используется `default_project` из `config_grok_queue.json`.
Положите изображения JPG/JPEG/PNG/WebP в `input`. Обрабатываются файлы непосредственно
в этой папке, по имени; подпапки не сканируются. Не меняйте очередь во время работы.

Запуск сам находит классификацию по содержимому файла (SHA-256), включая копии из
ART checkpoints. Совпадение имени вроде `source_01.jpg` недостаточно. Если описания
нет, модель описывает само изображение. Модель получает фотографию, подходящую
классификацию, список героев, цель фильма и пожелания к движению. Имена героев —
контекст фильма, а не основание для распознавания лиц. Промпт индивидуальный,
с приоритетом сохранения лиц, поз, предметов и минимального движения.

## Что должно быть настроено

- Python и зависимости проекта (`openai`, `Pillow`, `playwright`, `python-dotenv`), FFmpeg.
- `OPENAI_API_KEY` в существующем `.env` проекта или окружении. Промпты создаются
  через OpenAI API, а не через открытую беседу Codex. Изображение и связанное
  описание передаются API; модель задаётся в `prompt_model`. Используется
  [Responses API с изображением](https://developers.openai.com/api/docs/guides/images-vision).
- Открытый отдельный Chrome с debug-портом 9222, как в ранее использованном
  браузерном процессе. В нём должна быть ровно одна вкладка Grok Imagine с входом
  в аккаунт. Скрипт подключается к этому окну; не ищет координаты Windows.
- В Grok выбраны **6s, 720p**. Скрипт проверяет их до отправки и отключает звук.
  Эти два параметра пока фиксированы; интерфейс Grok может потребовать обновления селекторов.

Если рабочего окна Chrome ещё нет, откройте его существующим файлом
`open_ai_work_window.bat`, войдите в Grok при необходимости и затем запускайте
`run_grok_queue.bat BM26`. Уже открытое правильное окно используется повторно.
Закрывать предыдущий ролик вручную не нужно: очередь открывает чистую форму.

## Другие проекты, герои, папки

Скопируйте блок `BM26` внутри `projects`, назовите его, например, `BEN26` и измените:

| Поле | Назначение |
| --- | --- |
| `heroes` | Список героев фильма |
| `goal` | Цель и настроение фильма |
| `motion_guidance` | Пожелания к движению |
| `input_dir` | По умолчанию `input`, можно отдельную очередь |
| `delivery_config` | Обычный конфиг проекта с `final_videos_dir` и `regeneration_assets_dir` |
| `classification_file` | Каталог классификаций формата `media`; `null`, если его нет |
| `art_checkpoints_dir` | Папка ART checkpoints; `null`, если их нет |
| `prompt_model` | Доступная вашему API модель с поддержкой изображений и JSON schema |
| `cdp_url` | Локальный адрес Chrome, обычно `http://127.0.0.1:9222` |
| `upload_timeout`, `generation_timeout` | Таймауты в секундах |
| `remove_completed_inputs` | Удалять обработанные исходники из очереди после архивирования; `false` — оставлять |

Относительные пути в конфиге отсчитываются от самого файла конфига.
Выходные пути в обычном delivery config сохраняют прежнее правило: относительно
корня репозитория. Для разных проектов задавайте разные папки готовых видео.

```bat
run_grok_queue.bat BEN26
run_grok_queue.bat BM26 --input-dir "<LOCAL_PATH>"
run_grok_queue.bat BM26 --config-file "<LOCAL_PATH>"
run_grok_queue.bat BM26 --dry-run
run_grok_queue.bat BM26 --prepare-only
```

`--dry-run` проверяет конфигурацию и сопоставление без запросов к модели,
браузера и очистки. `--prepare-only` делает реальные запросы для промптов,
сохраняет план, но не запускает видео. Для выполнения — повторите обычную команду.

## Продолжение и очистка

Обычный повтор команды продолжает активный сохранённый план. Новые файлы,
добавленные после создания плана, попадут в следующую очередь после его завершения.
Не меняйте конфигурацию незавершённой очереди: продолжайте той же командой.
Промпты кэшируются по изображению, модели, описанию и задаче фильма. Прерванная
отправка с неизвестным результатом (`SUBMITTING`) требует проверки сохранённой
вкладки/состояния; автоматически второй ролик не заказывается.

Видео создаются последовательно. Перед каждым изображением открывается чистая
форма Imagine и проверяется загрузка картинки. MP4 проверяется FFmpeg, копируется
в папку проекта, сверяется по SHA-256, затем фиксируется в реестре. Исходник
сохраняется в архиве. В конце удаляются только успешно завершённые входные файлы
и подтверждённые рабочие дубликаты MP4. Остальные файлы `output` не затрагиваются.

Планы и журналы: `output/.grok-queues/`; реестр повторных запусков:
`output/.grok-completed/`. Эти данные нужны во время работы и повторных попыток,
но не обязаны оставаться в `output` после полного закрытия проекта.
До закрытия готовое изображение определяется по содержимому и папке назначения,
независимо от изменения промпта. Автоматической перегенерации при смене цели нет.

### Очистка после полного закрытия проекта

После архивирования завершённой очереди служебные записи можно удалить:

```bat
python scripts/cleanup_grok_state.py --config-file config_Hero.local.json --archive-manifest "<LOCAL_PATH>"
```

Сначала выводится точный список. Добавление `--execute` удаляет только эти записи.
Требуется манифест закрытия со статусом `ARCHIVED_AND_CLEANED`, списком `entries`
(`source`, `target`, `sha256`) и архивными планами очереди. Проверяются принадлежность
реестра папке назначения, существование и хеши готовых видео, совпадение записей
с архивом. Кэш удаляется только при доказанной связи промпта с этой очередью;
если есть другие живые планы, общий кэш сохраняется. Незнакомые записи остаются.

**Общий `output` не очищается целиком никогда.** Исходники, проекты, иные результаты
и чужие служебные данные не затрагиваются. Архив остаётся историей и автоматически
не загружается: после удаления реестра повторная ручная подача того же изображения
может создать новое видео. Блокировка нового BAT хранится в памяти Windows;
постоянный файл блокировки для новых запусков больше не создаётся.

Одновременный запуск двух новых BAT блокируется. Не запускайте параллельно старый
pipeline или отдельный prepared runner, работающий с тем же окном Chrome.
