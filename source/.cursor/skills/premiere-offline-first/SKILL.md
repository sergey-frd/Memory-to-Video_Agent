# Минимальное использование Premiere Pro

Предпочтение пользователя: выполнять как можно больше работы без открытого Premiere Pro и не делать его обязательным условием запуска скрипта. Это предпочтение способа исполнения, а не отмена требований к результату. Явные требования текущего задания имеют приоритет.

## Выбор способа исполнения

- Сначала проверь доступные скрипты, входные материалы и требования к результату. Для поддерживаемых операций используй Python, прямые API и FFmpeg: генерация, работа со звуком, аудит, подготовка JSON, монтаж, движение и предпросмотр.
- Не проси заранее открыть Premiere ради всего задания. Если Adobe действительно нужен, назови конкретную операцию и перенеси её после доступных автономных этапов. По возможности выполни необходимые Adobe-операции одним сеансом, без постоянного ручного управления интерфейсом.
- При доработке скриптов отделяй автономные стадии от Adobe-стадий. Проверяй наличие Premiere и подключения к нему только на стадии, которая их использует. Не добавляй запуск приложения как побочный эффект импорта модуля, аудита или автономного dry-run.
- Не заменяй выбранного пользователем провайдера генерации или способ озвучки только ради этой настройки. Прямой API не требует браузера; браузерный Grok-процесс может требовать открытого Chrome, но не Premiere.

## Монтаж и эффекты

Для правок `.prproj` сначала прочитай актуальный проект и нужную sequence; не используй старый аудит как доказательство текущего состояния. Подготовь JSON до изменения проекта, выполни предусмотренный исполнителем dry-run и затем примени проверенный план. Если dry-run отсутствует, не называй обычный запуск dry-run: используй безопасную копию и доступные проверки; обязательный dry-run из задания должен быть реализован и выполнен.

Сохраняй исходник и редактируемость результата. Предпочитай новый выходной проект; режим изменения существующего файла допустим согласно заданию и с резервной копией. Не переписывай файл, открытый в Premiere, офлайн: используй отдельный выходной путь либо согласуй безопасное сохранение и закрытие именно этого проекта. Не завершай чужие/несвязанные процессы Premiere ради освобождения файла.

Масштаб, pan, ключевые кадры и параметры цвета меняй в поддерживаемом графе проекта. Не считай произвольный эффект или версию `.prproj` поддерживаемыми без проверки. Если требуется редактируемый Motion/Lumetri, сохраняй нативные эффекты, ключевые кадры, исходники и JSON; один запечённый MP4 не выполняет это требование. Интенсивность движения, цвета и целевую громкость бери из текущего задания, а не из прежнего TASK.

## Когда требуется Adobe

- Создание JSX-файла ещё не означает применение эффекта. Вызовы `app.project`, QE, `openDocument` и `exportAsMediaDirect` в существующем JSX требуют работающего Premiere.
- Используй Adobe для неподдерживаемых автономным кодом операций, обязательного native export/readback и явно требуемого Premiere Desktop open-check. Например, требование open-check в TASK_032 сохраняется, даже если монтаж подготовлен автономно.
- Media Encoder может быть альтернативным Adobe-движком для финального рендера, но не заменяет среду исполнения Premiere JSX. До выбора этого маршрута проверь установленную версию, импорт sequence, медиа, эффекты и пробный экспорт. Не обещай уже готовую автоматизацию или совпадение результата без проверки.
- Удалённый Adobe-исполнитель — только возможная архитектура, пока он не настроен. Не предполагай его наличие и не переноси материалы на другой компьютер/сервис без соответствующего поручения.

## Проверка результата

После применения плана повторно прочитай новый проект: проверь sequence, тайминг, ссылки на медиа, параметры эффектов и ключевые кадры. Проверь фактический MP4/аудио по требованиям задания, включая слышимость речи, громкость, движение и цвет там, где они менялись.

Различай три результата: структурная проверка `.prproj`, предпросмотр FFmpeg и нативная проверка/рендер Adobe. FFmpeg собирает видео из источников и фильтров; он не является полным рендерером `.prproj`, Lumetri, вложенных sequence и сторонних плагинов. Его предпросмотр может быть приближением. Если заданию достаточно самостоятельного MP4 и его эффектов FFmpeg, можно закончить без Adobe. Если нужен точный нативный результат, не объявляй его подтверждённым по одному FFmpeg-preview.

Если Adobe недоступен, выполни все независимые этапы и перечисли оставшиеся нативные проверки. Не отмечай невыполненные open-check или QA как PASS.

| Motion и монтаж по JSON | `utils/premiere_sequence_motion.py`, `utils/premiere_sequence_insert_motion.py`; схемы и команды — `docs/PREMIERE_JSON_EDIT_AND_MOTION_RU.md`. |
| Lumetri | Примеры автономного изменения поддерживаемых параметров: `main_premiere_task_031_art_final.py`, `main_premiere_task_033_fit_pulse_fill.py`. Это не универсальная поддержка всех эффектов. |

| Озвучка TTS | Выделенного интегрированного TTS-этапа при проверке не найдено. Проверь, не появился ли он; не выдавай наличие внешнего TTS API за готовую функцию проекта. |
