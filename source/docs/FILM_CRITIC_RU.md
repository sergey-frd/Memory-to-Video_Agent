# Финальный проход кинокритика

Опция включена по умолчанию. Она выполняется после нативной сборки и технического
QA, на фактическом готовом визуальном результате. Агент меняет роль: оценивает
фильм как строгий кинокритик, режиссёр и художник, не защищая собственный план.
Это дополнительная проверка результата после двух проходов планирования.

## Просмотр и замечания

Сначала посмотреть native render целиком, затем пройти все кадры последовательно.
Особое внимание: начало/финал, каждой склейке, пикам пульса, движущимся лицам,
надписям, границам crop, скачкам масштаба/цвета, артефактам ART и повторяемости
эффектов. Подозрительные участки просмотреть замедленно и покадрово. Разреженные
пробы, исходные изображения и FFmpeg-реконструкция проекта не заменяют эту проверку.
Звук и будущая музыка не оцениваются. Полный native render нужен именно для этого
QA; его подготовка остаётся ручной Adobe-операцией в рамках задания, не скрытым
автоматическим экспортом.

Каждое замечание содержит ID, важность (blocking/major/minor), диапазон кадров
`[start,end)` на timeline, ID затронутых сцен, конкретное наблюдение, визуальное
доказательство, минимальное исправление и объяснение пользы. Не придумывать
замечания ради количества. Изменения монтажа, меняющие утверждённую структуру,
оформлять как её отдельную редакцию; не скрывать их внутри цветового/Motion-плана.

## Исправление и остановки

По умолчанию разрешён один цикл коррекции. Агент готовит исправления в новом
WORK-проекте/sequence, сохраняет исходную версию и render, выполняет offline
preflight и останавливается на `USER_ACTION_REQUIRED` перед необходимым Adobe.
Пользователь запускает JSX; агент проверяет настоящие журналы и сохранённый проект.

Затем агент смотрит новый native render целиком, снова проходит все кадры и
перепроверяет каждое исходное замечание. Оно не может исчезнуть из отчёта без
явного результата проверки. Исправление подтверждается новым project/render,
контрольными суммами, цепочкой отчётов и конкретным `recheck_evidence`.

Если замечаний нет или они устранены: `VISUAL_READY_WAITING_MUSIC`, затем остановка.
Если замечания остались после одного цикла: `CRITIC_ISSUES_REMAIN`, затем остановка
со списком проблем. Бесконечной самопеределки нет. Осознанно отложенная minor-правка
может остаться в отчёте; blocking/major не позволяют объявить визуальную готовность.
Пользователь накладывает музыку после этой остановки. Финальная версия с музыкой
требует отдельного просмотра: нынешний статус не означает готовый музыкальный релиз.

## Настройка и контракт

В JSON структуры, передаваемой пакету творческого плана, опционально:

```json
{
  "critic_review": {
    "enabled": true,
    "max_correction_rounds": 1,
    "pause_before_native": true,
    "pause_before_music": true
  }
}
```

Без поля действуют эти значения. `enabled: false` отключает художественный проход,
но не технический QA. `max_correction_rounds: 0` даёт только review с остановкой
при замечаниях. Этот контракт не добавлен в старую schema `task.json` и AUTO runtime;
не вставлять поле туда до соответствующей интеграции.

Пакет создаёт `scripts/film_critic_review.py`:

```powershell
python scripts/film_critic_review.py packet --structure <LOCAL_PATH> --project <LOCAL_PATH> --render <LOCAL_PATH> --native-record <LOCAL_PATH> --output <LOCAL_PATH>
python scripts/film_critic_review.py check --report <LOCAL_PATH>
python scripts/film_critic_review.py check --report <LOCAL_PATH> --previous <LOCAL_PATH>
```

`native_result.json` — запись действительного проверенного native исполнения:
`engine` (Premiere/Adobe Media Encoder), `sequence_name`, `project_sha256`,
`render_sha256`, `frames`, `fps`. Её составляют по реальным Adobe logs/readback и
файлам; не выдают FFmpeg-preview за Adobe, не создают фиктивную запись для обхода.

Отчёт содержит исходные артефакты и hashes, `continuous_watch_complete`, полное
`frame_by_frame_ranges`, `reviewed_scene_ids`, `reviewed_boundaries`,
`overall_assessment`, `issues`, `audio_evaluated: false`, `correction_round`.
При коррекции указать `previous_review_sha256`; если sequence переименована —
`previous_sequence_name`. Каждое замечание: `id`, `severity`, `frame_range`,
`scene_ids`, `observation`, `evidence`, `proposed_fix`, `reason`,
`status` (OPEN/RESOLVED/DEFERRED). У RESOLVED обязательно `recheck_evidence`.
Новая версия должна сохранять предыдущие project/render как отдельные файлы.

Пакет сам не смотрит видео, не извлекает каждый кадр и не исправляет проект.
Просмотр выполняет агент доступными инструментами, сохраняя evidence в каталоге
задачи. Checker проверяет целостность файлов, полноту заявленного покрытия,
привязку замечаний и ограничения цикла. Он не доказывает, что агент действительно
увидел каждый кадр, и не заменяет художественное суждение. Автоматический native
исполнитель единого плана по-прежнему требует адаптации, указанной в
[CREATIVE_FINISH_RU.md](CREATIVE_FINISH_RU.md).
