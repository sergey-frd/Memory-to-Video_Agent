# Один нативный проход Premiere: Max26

Исполнитель подготовки: `tools/prepare_native_finish.py`. Локальная конфигурация:
`config_native_finish_Max26.local.json`. Вход — BEST ASSEMBLY, review 4, 108 секунд,
12 фрагментов. Черновик 720p используется для выбора монтажа; нативная сборка
читает оригинальные медиа и IN/OUT из сохранённого монтажного плана.

```powershell
.\run_prepare_native_finish.bat config_native_finish_Max26.local.json --dry-run
.\run_prepare_native_finish.bat config_native_finish_Max26.local.json
```

Первая команда проверяет конфигурацию, контрольные суммы, пустую исходную
последовательность и допустимость эффектов. Вторая создаёт новую папку под
`output/Max26/native_finish/`: одну копию `.prproj`, один `finish_all.jsx`, job.json,
план переходов, входные контрольные суммы и `START_RU.md` с точными путями.
Adobe и API на стадии подготовки не запускаются.

## Один запуск в Adobe

Открыть созданную рабочую копию проекта и один раз выполнить `finish_all.jsx`
через существующую панель Run Transition Script. Ручной выбор отдельных
скриптов движения, переходов и цвета больше не требуется.

Скрипт дублирует пустую M_26_1, собирает монтаж и создаёт в том же проекте:

1. `MAX26_01_ASSEMBLY` — монтаж из оригиналов, 1920×1080, 25 fps.
2. `MAX26_02_MOTION` — редактируемое движение единственной фотографии.
3. `MAX26_03_TRANSITIONS` — переход после салюта.
4. `MAX26_04_FINAL` — индивидуальный и общий Lumetri.

После каждого этапа проверяются размещения и неизменность предыдущих
контрольных последовательностей, проект сохраняется. После FINAL выполняется
ровно один вызов нативного экспорта в `Max26_FINAL_1080p.mp4`.
Успешное создание файла означает `EXPORT_FILE_CREATED_REQUIRES_MEDIA_QA`,
а не окончательную приёмку качества.

## Профиль Max26

- Фото: увеличение Scale на 6%, пик на 58% длительности, частичный возврат 18%.
- Один Cross Dissolve 0,4 с на 84-й секунде. Исходные кадры с обеих сторон
  доступны; остальные склейки остаются прямыми.
- Индивидуальный Lumetri нейтрален, доступен для дальнейшей настройки.
  `color.overrides` позволяет задать поправки по material ID из edit_plan.
- Общий профиль warm_family, сила 20%: Temperature +1,2; Contrast +0,8;
  Highlights −1,6; Shadows +1; Saturation 100,8. Это мягкое предложение для
  просмотра, не подтверждённая цветокоррекция кожи/баланса белого.
- Сохраняется оригинальное аудио клипов. Нормализация громкости, чистка речи,
  музыка, титры и анализ окончаний реплик в этот пакет не входят.

## Ограничения и проверка

Исполнитель использует существующие тела JSX сборки, Motion, Cross Dissolve и
Lumetri. Эффекты и переходы используют QE и имена параметров установленного
Premiere; соответствие версии и языка интерфейса подтверждается только
нативным запуском. При неподдержанном параметре или несовпадении readback
экспорт останавливается. Скрипт не переписывает исходный Adobe-проект и не
закрывает другие проекты.

Повторный запуск поверх частично выполненной копии запрещён. Автоматическое
продолжение после сбоя пока не реализовано: сохранить `finish_progress.log`,
устранить причину, подготовить новую папку и запустить новую чистую копию.
Готовый MP4 тоже не перезаписывается.

Проверено локально: preflight фактического Max26, Python-тесты контроллера и
переиспользуемых этапов, синтаксис сгенерированного JavaScript. Это не нативный
open-check. Проверить в Premiere движение фотографии, границы перехода,
изменение цвета и независимость контрольных последовательностей; затем
просмотреть экспорт со звуком и проверить разрешение, длительность и декодирование.

Новый пакет не меняет состояние одобрения workflow и не выдаёт имитацию
успешного прохождения прежних раздельных native/animation/transitions/color
этапов. Пока это отдельный исполнитель финальной обработки.


## Последнее исправление: ложная ошибка Project save failed

Дата: 17.09.2026.

Первый запуск Max26 остановился после сборки с сообщением:
`operation=verify all final video placements; Error: Project save failed`.
Проверка файла на диске показала, что Premiere уже сохранил последовательность
MAX26_01_ASSEMBLY: 12 клипов, 108 секунд. Ошибка относилась к проверке результата
вызова сохранения, а не к отсутствию сохранённого монтажа.

Прежняя проверка `app.project.save() !== 0` считала ошибкой любое значение,
которое не является именно числовым нулём. При этом фактический тип/значение
ответа первого запуска не журналировались; нельзя утверждать, что Premiere
вернул именно true, undefined или строку.

Теперь функция checkpoint делает следующее:

1. Повторно проверяет монтажные позиции и контрольные последовательности.
2. Помечает текущую операцию как `save checkpoint <имя>`, чтобы ошибка указывала
   на сохранение, а не на предыдущую проверку клипов.
3. Запоминает время начала сохранения и вызывает `app.project.save()`.
4. Пишет в журнал значение ответа и его JavaScript-тип.
5. Создаёт новый объект File для ожидаемого рабочего проекта и проверяет:
   файл существует, размер больше нуля, время изменения не старше момента
   вызова минус две секунды. Допуск учитывает точность времени файловой системы.
6. Только после этого фиксирует контрольную точку и переходит к следующей стадии.

Проверка времени/размера — свидетельство записи файла, а не полная проверка
сохранённого графа проекта. Нативный визуальный контроль и чтение выходного
проекта после выполнения всё ещё нужны. Если сохранение действительно не
подтверждено, исполнитель останавливается до финального экспорта.

Добавлен тест разных возвращаемых типов при подтверждённой записи, а также
отказа при устаревшем времени файла даже при ответе 0. Пять тестов контроллера
прошли. После исправления подготовлена новая чистая копия; полный успешный
нативный проход новой версии на момент этой записи ещё не подтверждён.

## Повторное применение к Максу и Аркадию

Общая технология одна: выбрать монтаж → получить edit_plan → проверить входы →
создать рабочую копию и JSX → один запуск в Premiere → проверить финал.
У каждой задачи должны быть собственные конфигурация, выходная папка,
контрольные последовательности и привязка к конкретному review.

| Параметр | Max26 | Arkady26 |
|---|---|---|
| Конфиг подготовки | config_native_finish_Max26.local.json | отдельный config_native_finish_Arkady26.local.json, ещё не подготовлен здесь |
| workflow_state | output/Max26/workflow/workflow_state.json | output/Arkady26/workflow/workflow_state.json — проверить наличие и актуальность |
| review_index | 4 — BEST ASSEMBLY в проверенном состоянии | определить по фактическому массиву reviews |
| edit_plan | план выбранной BEST ASSEMBLY Max26 | точный plan выбранной редакции Аркадия |
| project | BAM_26_e1.prproj по полному пути из конфига | тот же исходный проект указан в локальном pipeline Аркадия |
| target_sequence | M_26_1 | A_26_1 — проверить, что ещё пуста |
| output_root | output/Max26/native_finish | output/Arkady26/native_finish |
| checkpoint_names | MAX26_01_ASSEMBLY и следующие | четыре уникальных имени ARKADY26_01_ASSEMBLY и следующие |

`review_index` — номер записи reviews начиная с 1. Это не обязательно номер
Alt: после редакций и BEST ASSEMBLY нумерация может расходиться. Исполнитель
проверяет, что edit_plan совпадает с plan выбранной записи и что сохранённые
контрольные суммы не изменились. Он не подменяет выбранный план последним по дате.
Состояние workflow читается, но само по себе не помечается утверждённым.

### Поля конфигурации и их назначение

- `schema_version`: 1.
- `workflow_state`, `review_index`, `edit_plan`: фиксируют конкретный монтаж.
- `project`, `target_sequence`: проект-шаблон и пустая исходная последовательность.
- `preset`: существующий установленный экспортный файл .epr.
- `output_root`: отдельная папка задачи; каждый запуск создаёт новую подпапку.
- `width`, `height`: текущий профиль поддерживает только 1920×1080; монтаж 25 fps.
- `checkpoint_names`: ровно четыре различных имени; они не должны уже
  присутствовать в исходном проекте или совпадать с target_sequence.
- `animation.enabled`, `peak_fraction`, `zoom_fraction`, `return_fraction`:
  включение и форма движения фотографий. Видеоклипам это движение не добавляется.
- `transitions.enabled`, `duration_seconds`, `minimum_clip_seconds`:
  параметры Cross Dissolve и минимальная длина соседних видео.
- `transitions.cut_frames`: конкретные монтажные стыки в кадрах от начала
  НОВОГО выбранного плана. Например, 84 × 25 = 2100 для текущего Max26.
  Это значение нельзя переносить на другой монтаж автоматически.
- `color.enabled`, `default_correction`, `overrides`, `global_look`:
  индивидуальные поправки и общий цвет. Ключи overrides — реальные material ID
  выбранного плана; неизвестные ID отклоняются.
- `notes`: пояснения; сами по себе не меняют обработку.

Пути конфигурации разрешаются относительно папки самого JSON. Пути медиа
в монтажном плане должны оставаться доступными. Требуется исходный материал,
а не только MP4 720p: из одного черновика нельзя восстановить прежнюю детализацию,
исходные диапазоны и редактируемые эффекты.

### Что нельзя слепо переносить из Max26

Не копировать review_index=4, material ID, тайм-код перехода 84 с и творческий
цветовой профиль как обязательные параметры Аркадия. Сначала изучить его план,
длительности и сцены. Контроллер проверяет наличие запасных кадров для перехода:
если указанный стык не подходит, подготовка завершится ошибкой, а не применит
переход в другом месте. При необходимости можно отключить переходы.

Не переносить файлы job.json и finish_all.jsx между задачами: в них уже встроены
конкретные пути, исходники, последовательности и параметры эффектов.

### Важная текущая граница переиспользования

Имена файлов и заголовок START_RU.md теперь задаются параметром `output_prefix`
(например, `Ben26`; по умолчанию `Max26` для совместимости). Поддерживаются
три или четыре уникальные контрольные последовательности. В варианте из трёх
переходы и цвет применяются в последней последовательности перед сохранением.
Самовольное переименование уже подготовленных файлов нарушит привязку JSX
к job.project/job.video. Конфиг Аркадия и его нативный пакет в рамках этой
документационной правки не создавались.

## Практический порядок работы после подготовки

1. Проверить dry-run соответствующего конфига. Он не запускает Premiere.
2. Сгенерировать пакет. Сохранить путь к выведенному START_RU.md.
3. Открыть только указанную рабочую копию и запустить её JSX. Не путать папки
   разных запусков. Скрипт проверяет путь открытого проекта.
4. Дождаться статуса финального экспорта либо ошибки. Во время работы не
   редактировать последовательности вручную и не запускать второй экземпляр.
5. При ошибке сохранить журнал и контрольные копии; не повторять обработку
   поверх уже созданных контрольных последовательностей. Подготовить новый
   пакет после исправления причины.
6. После экспорта проверить 1080p, длительность, полноту декодирования, лица,
   движение, переходы, цвет, речь и громкость. Один финальный MP4 и сообщение
   об успешном экспорте не заменяют просмотр.

Эта схема сокращает ручные запуски и промежуточные экспорты. Она не означает,
что художественное качество цвета, кадрирования и звука уже автоматически
подтверждено, и не является AI-апскейлом 720p.


## Исправление формата Max26 — 18.09.2026

Для Max26 актуален UHD 4K **3840×2160, 25 fps**, как в исходной пустой M_26_1.
Указания 1920×1080 выше описывают прежний ошибочный пакет, а не нужный финальный
формат. Сохранённый MAX26_01_ASSEMBLY из пакета 20260917_100412_9f3b1b73 был
1920×1080. Read-only проверка подтвердила совпадение всех 12 размещений, исходных
IN и тайминга 108 секунд с BEST ASSEMBLY edit_plan.

Новая конфигурация: `config_native_finish_Max26_4k.local.json`.
Источник проекта — сохранённая рабочая копия с ASSEMBLY; существующие
последовательности сохраняются. Новый JSX восстанавливает тот же монтаж из
оригинальных медиа, используя пустую M_26_1, в отдельных последовательностях
MAX26_4K_01_ASSEMBLY → MAX26_4K_02_MOTION → MAX26_4K_03_TRANSITIONS →
MAX26_4K_04_FINAL. Это не увеличение готового 1080p MP4.

```powershell
.\run_prepare_native_finish.bat config_native_finish_Max26_4k.local.json --dry-run
.\run_prepare_native_finish.bat config_native_finish_Max26_4k.local.json
```

Новый пакет находится под `output/Max26/native_finish_4k/`. Открыть новую копию
MAX26_FINISH_WORK.prproj и запустить finish_all.jsx из той же папки.

финальной последовательности; реальный MP4 после нативного экспорта нужно
проверить на 3840×2160, 25 fps и длительность. Подготовка пакета не означает,
что экспорт 4K уже выполнен. Детализация каждого кадра ограничена оригиналом.
Старые пакеты и их конфигурации оставлены как история; для нового запуска
Max26 использовать именно конфигурацию с суффиксом _4k.
