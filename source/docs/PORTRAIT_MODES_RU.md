# Настройки портрета для любого героя

Выбор по смысловой цели, включая художественный, интегрированный и альтернативный варианты: [Как выбрать монтажный вариант](PORTRAIT_WORKFLOW_CHOICES_RU.md). Это редакторские сценарии; они не все реализованы отдельными режимами launcher.

Эти режимы выбираются для конкретного задания. Они не меняют старые планы и не определяют обязательную длительность для всех героев. Основа отбора — актуальное описание человека (`hero_config` → `human_detail_txt`), подтверждённое содержание материалов и пожелания пользователя. Неизвестные личности, даты, отношения и события остаются неизвестными. Метафора не заменяет документальное доказательство.

## Реальные поля и зависимости

| Задача | Поля | Эффект и необходимые входы |
| --- | --- | --- |
| Общие входы FULL | `schema_version: 1`, `hero_config`, `classification_result`, `expected_count`, `output_root`, `model`, `narrative` | Полный классифицированный каталог, существующие файлы с совпадающими SHA256; актуальная характеристика героя. Отдельный `output_root` для нового варианта. |
| Компактный FULL | `duration_mode: "compact"`, `max_duration_seconds: 360` | Верхняя граница, не минимальная длительность. В старых конфигах отсутствие `duration_mode` означает compact. |
| FULL по полноте | `duration_mode: "coverage"` | Нет общей квоты времени. `max_duration_seconds` и `target_duration_seconds` должны отсутствовать или быть null. Ненулевой лимит отклоняется. Новая сторона героя оправдывает новую сцену; повтор очевидного — нет. |
| Равноправие типов | `media_type_policy: "equal"` | Исходные фото, видео, акварели и DE конкурируют по смыслу. Старые preferred-оценки ART не служат правилом приоритета. |
| Приоритет подходящих ART | `media_type_policy: "legacy"` либо отсутствие поля; явное указание в `narrative` | Это редакторское указание, а не числовое ранжирование в коде. Пример: «Предпочитай подходящие ART, если они лучше раскрывают смысл; не включай автоматически все». Отдельного реализованного enum `art_priority` у launcher нет. |
| Карта раскрытия | `coverage_map` | JSON с массивом `facets`: `id`, `title`, `candidate_ids`, `evidence`, `gap` (допустимы поясняющие поля). Кандидаты — примеры, не whitelist. Planner возвращает `coverage_audit` для каждой грани: `facet_id`, `selected_ids`, `reason`, `gap`. Ссылки должны вести на выбранные кадры; пропущенной грани нужен явный пробел. |
| Общие входы SHORT | `schema_version: 1`, `source_edit_plan`, `classification_result`, `output_root`, `model`, `narrative` | Явный FULL-план, его исходники и каталог. Только его ID, не больше исходной длительности каждого кадра, без расширения видеодиапазона. FULL MP4 и FULL_LOCK не требуются. |
| SHORT с фиксированными границами | Отсутствие `duration_mode: "semantic_ratio"` | Текущий legacy launcher проверяет 60–180 секунд. Это зашитый старый режим, а не произвольные конфигурируемые min/max: таких полей у SHORT нет. |
| SHORT по смысловой доле | `duration_mode: "semantic_ratio"`, `approximate_fraction: 0.3333333333` | Мягкий ориентир около трети FULL, без квоты 60–180 и точного коэффициента. Длительность строго меньше собственного FULL. Сокращение отбором смысловых опор, не пропорциональным ускорением. `media_type_policy` и `coverage_map` поддерживаются также здесь. |
| Способ запуска | BAT + конфиг; `--check` или `--dry-run` | Один и тот же pipeline для ручного CMD-запуска и явно разрешённого запуска агентом. Проверка не вызывает API/рендер. SHORT без собственного FULL-плана выдаёт `WAITING_DEPENDENCY`, не подставляет старый план. |

## Классификация и происхождение

Исходники классифицируются один раз. Готовые ART анализируются по фактическим изображениям, затем добавляются к исходному каталогу с `art_source_id`, `art_style`, SHA256 и оценкой. `run_integrate_art.bat CONFIG` выполняет этот отдельный этап. Наличие ART-файла не равно художественной приёмке. В FULL сохраняется `art_selection.json` с выбранными ID, оригиналами и причинами; точный план сохраняет исходные пути и хеши. SHORT сохраняет ссылку и хеш собственного FULL-плана.

## Универсальные примеры

Ниже пример FULL-конфига для нового героя. Пути заменяются фактическими абсолютными путями, `expected_count` — проверенным числом строк каталога. Каталог должен уже существовать, карта — содержать реальные ID.

```json
{
  "schema_version": 1,
  "hero_config": "<LOCAL_PATH>",
  "classification_result": "<LOCAL_PATH>",
  "expected_count": 100,
  "output_root": "<LOCAL_PATH>",
  "model": "gpt-4.1-mini",
  "duration_mode": "coverage",
  "media_type_policy": "equal",
  "coverage_map": "<LOCAL_PATH>",
  "narrative": "Раскрой подтверждённые стороны героя без квоты времени. Каждый кадр добавляет смысл; пробелы фиксируй честно."
}
```

Для compact заменить `duration_mode` на `compact`, добавить `max_duration_seconds` с нужным потолком. Для предпочтения подходящих ART выбрать `legacy` и сформулировать правило в `narrative`. Не менять конфиг уже выполняющегося задания.

```json
{
  "schema_version": 1,
  "source_edit_plan": "<LOCAL_PATH>",
  "classification_result": "<LOCAL_PATH>",
  "output_root": "<LOCAL_PATH>",
  "model": "gpt-4.1-mini",
  "duration_mode": "semantic_ratio",
  "approximate_fraction": 0.3333333333,
  "media_type_policy": "equal",
  "coverage_map": "<LOCAL_PATH>",
  "narrative": "Самостоятельный короткий портрет из указанного FULL. Сохрани ключевые качества, смысловые начало и окончание; около трети без точной квоты."
}
```

```bat
run_portrait_draft.bat "<LOCAL_PATH>" --check
run_portrait_draft.bat "<LOCAL_PATH>"
run_short_portrait.bat "<LOCAL_PATH>" --check
run_short_portrait.bat "<LOCAL_PATH>"
```

## Прогресс, продолжение и честные ограничения

Консоль и файлы показывают проверку N/total, API-стадию и ограниченное ожидание, FFmpeg frame/time/speed, сборку MP4 и полное декодирование. Ожидание не считается выполнением. Неопределённый API-запрос не повторяется автоматически; сохранённый ответ можно исправить редакторски с журналом изменений вместо нового запроса. Сохранённая структура и готовый MP4 используются повторно. Прерванный рендер пока собирает сегменты заново в новом каталоге — покадрового resume нет.

Для HEIC нужен `pillow-heif` в Python-окружении самого BAT. 720p собирается офлайн без Adobe; исходное видео сохраняет звук, фотографии беззвучны. Музыка, TTS, титры, переходы и нативные эффекты не создаются этим этапом. Техническое декодирование не является художественной приёмкой; обе первые версии предназначены для общего просмотра и последующих правок. Передача биографических данных в API и платный запуск требуют разрешения пользователя; ручной и агентский запуск используют одинаковые исполняемые файлы.
