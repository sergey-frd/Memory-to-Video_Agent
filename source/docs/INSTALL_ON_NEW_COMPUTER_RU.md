# Установка той же версии на новом компьютере

Выпуск **2026.08.31.01**, тег **v2026.08.31.01**.

Для личного ноутбука используйте **img-style-ag_1** — основной репозиторий разработки на GitHub. «Внутренний» означает его назначение и приватность, а не хранение только на десктопе.

| Репозиторий | Назначение | Каталог запуска |
| --- | --- | --- |
| `sergey-frd/img-style-ag_1` | Исходный код и история разработки; доступ вашей учётной записи | Корень клона |
| `sergey-frd/Memory-to-Video_Agent` | Публичный выпуск: отфильтрованная копия кода, документация, примеры | `source/` внутри клона |

Достаточно **одного** репозитория. Они не являются зависимостями друг друга. В основном репозитории старую папку `source/` для запуска не используйте. Коммиты двух репозиториев различаются, поскольку структура и фильтрация публикации различаются; номер выпуска общий.

## Установка на Windows

1. Установите Git for Windows и **Python 3.14.2, Windows x86-64**. Включите Python в PATH. Проверьте `git --version`, `python --version` и `python -c "import platform; print(platform.machine())"`: нужны Python `3.14.2` и `AMD64`.
2. Откройте PowerShell в каталоге для программы. Выполните команды ниже. Если Git запросит вход, авторизуйтесь своей учётной записью GitHub; не вставляйте токен в URL.

```powershell
git clone https://github.com/sergey-frd/img-style-ag_1.git
cd img-style-ag_1
git switch --detach v2026.08.31.01
.\install_project.bat
.\run_verify_installation.bat --require-tag
```

Установщик создаёт `.venv`, устанавливает версии из `requirements-lock-windows-py314.txt`, проверяет зависимости и создаёт локальную конфигурацию. Существующие `.env` и `config.local.json` сохраняются. При ошибке возвращается ненулевой код и установка останавливается. Не копируйте `.venv` с десктопа: окружение создаётся заново.

Если Python несколько, укажите нужный: `install_project.bat -PythonExe "ПОЛНЫЙ_ПУТЬ_К_python.exe"`. Для нестандартного окружения доступны `-VenvDir`, `-ConfigFile`. `-Unlocked` устанавливает незакреплённые зависимости для разработки и **не** воспроизводит окружение выпуска. `-InstallChromium` дополнительно устанавливает Chromium Playwright. `-ForceConfig` намеренно перезаписывает выбранный конфиг.

`detached HEAD` здесь нормально: это фиксация выпуска. Для разработки после установки создайте ветку: `git switch -c laptop-work`.

Публичная альтернатива, если приватный репозиторий не нужен:

```powershell
git clone https://github.com/sergey-frd/Memory-to-Video_Agent.git
cd Memory-to-Video_Agent
git switch --detach v2026.08.31.01
cd source
.\install_project.bat
.\run_verify_installation.bat --require-tag
```

Проверяющая программа учитывает, что публичный `VERSION` находится на уровень выше `source/`.

## Что перенести отдельно

### Постоянные инструкции Codex и Cursor

В рабочую копию после выпуска `2026.08.31.01` добавлены `AGENTS.md` и `.cursor/skills/premiere-offline-first/SKILL.md`. Они задают предпочтение: генерация, монтаж, звук и предпросмотр по возможности без Premiere; Adobe нужен только для конкретных нативных операций и обязательных проверок. Старый тег `v2026.08.31.01` этих файлов ещё не содержит.

Открой в Codex каталог запуска: корень основного репозитория либо `source/` публичного выпуска, содержащего эти файлы. `AGENTS.md` направляет агента к проектному skill; личную папку Codex переносить для этого не требуется. Это [механизм проектных инструкций Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Cursor использует тот же файл в `.cursor/skills/`. Если инструкции не подхватились в уже открытой задаче, начни новую задачу в этом каталоге.

Для использования вне этого проекта можно отдельно установить папку `premiere-offline-first` из `.cursor/skills/` в личный каталог `$CODEX_HOME/skills` (если переменная не задана — `%USERPROFILE%\.codex\skills`). При обновлении сверяй личную копию с репозиторной. Skill — инструкция агенту: он не устанавливает Adobe/TTS, не меняет уже существующие скрипты автоматически и не гарантирует совпадение FFmpeg с нативным рендером.

### Рабочие материалы и приложения

Git переносит программу, но не заменяет полную резервную копию монтажного рабочего места.

| Данные или программа | Действие |
| --- | --- |
| `.env`, API-ключи | Заполнить локально или перенести защищённым способом; не отправлять в Git |
| `config.local.json`, `*.local.json` | Перенести отдельно, исправить пути |
| `.prproj`, фото, видео, музыка, результаты и отчёты TASK | Скопировать отдельным архивом/диском, проверить комплектность |
| Premiere Pro, плагины, шрифты | Установить отдельно, использовать те же версии для сопоставления рендера |
| Chrome, авторизация сервисов | Установить Chrome и войти заново; не переносить браузерный профиль через Git |

Можно сохранить прежние буквы дисков и каталоги. Если пути изменились, исправьте JSON и выполните **Link Media** в Premiere. Копирование одного `.prproj` не переносит связанные материалы.

Для ART-процедур копируйте пример рядом с ним, чтобы сохранить базу относительных путей:

```powershell
Copy-Item .\examples\premiere\art_task_032.example.json .\examples\premiere\art_task_032.local.json
notepad .\examples\premiere\art_task_032.local.json
.\run_premiere_art_task.bat --task 032 --config .\examples\premiere\art_task_032.local.json --stage check
```

Заполните все пути. `check` читает проект, но не монтирует и не заменяет dry-run. [Порядок TASK_031–034](PREMIERE_ART_TASKS_031_034_RU.md).

## Как убедиться, что версия совпала

На обоих компьютерах выполните `run_verify_installation.bat --require-tag`. В **одном и том же репозитории** должны совпасть версия, тег и полный `git_head`; Python и пакеты lock-файла должны пройти проверку. Команда не читает секреты, не открывает Premiere и не выполняет художественную приёмку.

Код и версии Python-пакетов фиксируются выпуском. Побитно одинаковый рендер дополнительно зависит от Premiere, эффектов, шрифтов, исходников, GPU и драйверов. Сетевые AI-сервисы меняются независимо от Git, поэтому их ответы не гарантируются одинаковыми.

```powershell

git tag --sort=-version:refname
```

Посмотрите тег на десктопе, выберите **тот же** на ноутбуке командой `git switch --detach ИМЯ_ТЕГА`, повторите установку и проверку. `git pull` из `main` может получить более поздний код и не фиксирует конкретный выпуск.
