# Подготовка одного нативного прохода

`tools/prepare_native_finish.py` готовит отдельную рабочую копию Premiere-проекта, JSX, монтажный план и журналы. Adobe и генерация через API при подготовке не запускаются. Вход — утверждённый review из workflow и соответствующий монтажный план с исходными медиа и IN/OUT.

Скопируйте `config_native_finish.example.json` в личный `*.local.json`. Заполните пути проекта, состояния workflow, монтажного плана и установленного `.epr`, индекс принятого review, имя пустой исходной sequence и уникальные имена контрольных последовательностей. Имя героя задаётся через `output_prefix`. Пример требует заполнения и сам по себе не является готовым заданием.

```bat
run_prepare_native_finish.bat config_native_finish_HERO.local.json --dry-run
run_prepare_native_finish.bat config_native_finish_HERO.local.json
```

Первая команда проверяет входы без сборки. Вторая создаёт пакет для ручного запуска. Пользователь открывает подготовленную копию и выполняет `finish_all.jsx` через Run Transition Script один раз. Скрипт создаёт контрольные последовательности сборки, движения, переходов и цвета, проверяет их, сохраняет проект и выполняет один нативный экспорт.

Этот исполнитель предусматривает экспорт; он не выбирается автоматически для задачи, где нужен только редактируемый проект. Анимация, переходы и цвет включаются согласно заданию и конфигурации. Подготовленный JSX, успешная запись проекта, созданный MP4 и визуальная приёмка — отдельные состояния. После запуска проверяются реальный журнал, сохранённый проект и полученное видео.

При ошибке частичную сборку не запускают повторно без проверки. Исходники и принятые результаты сохраняются. Общая технология описана в [FULL / MINIMAL](FULL_MINIMAL_PRODUCTION_RU.md); первая структура использует [принцип компактности](COMPACT_FIRST_RU.md).
