# Единое визуальное доведение структуры

Обновлено 3 октября 2026. Предпочтительная технология новых задач: после
утверждения структуры агент принимает связанные творческие решения за два прохода.
Motion, переходы и цвет не планируются независимо для всего фильма.

## Маршрут с нуля

TASK + конфигурация + INIT → классификация исходников и ART → расширенный WIDE →
редакторский FULL → независимые MAIN/SHORT → утверждённая структура каждой версии →
единый творческий план → нативная сборка/применение → технический QA →
кинокритик → один цикл исправлений и перепроверка → остановка → музыка пользователя.

Финальный [проход кинокритика](FILM_CRITIC_RU.md) включён по умолчанию. Он оценивает
готовый native render, а не исходники или план. При отсутствии/устранении замечаний
результат — `VISUAL_READY_WAITING_MUSIC`; при оставшихся проблемах — остановка
`CRITIC_ISSUES_REMAIN`. Отключение опции не отменяет техническую проверку.

WIDE — полный материал для отбора; FULL — содержательный мастер после удаления
избыточности. MAIN и SHORT имеют собственные задачи и форматы. Новая процедура
не отменяет классификацию и редакторский отбор: выразительное движение не исправляет
плохую структуру. Для уже собранного пользователем монтажа вход сразу на утверждённую
структуру; остальные творческие шаги те же.

## Проход 1: сцена и следующий стык как одно решение

Агент смотрит реальную фотографию либо видеофрагмент, его начало/середину/конец,
затем следующую сцену. Оценивает смысл, лица, текст, естественное движение,
направление взгляда, крупность, яркость и цвет. Для видео трёх проб может быть
недостаточно: тогда просматривает дополнительные моменты или весь фрагмент.

На одной паре агент одновременно выбирает:

- композицию сцены и Motion: неподвижность, pan, zoom либо мягкий пульс;
- характер выхода и входа соседних сцен, прямую склейку либо оправданный переход;
- цветовые поправки и согласование пары;
- объяснение решения и возможную точку пика для будущей музыки.

Далее переходит к следующей паре до конца фильма. У каждой сцены и каждой
границы есть явное решение, включая «оставить», «без движения», «прямая склейка».
Пульс предпочтителен там, где поддерживает сцену: плавное изменение с возвратом
к исходной композиции. Не одинаковый эффект на всех объектах. Короткие вставки,
живое движение, уже анимированный ART или лица у границы кадра могут требовать hold.
Не растягивать изображение и не жертвовать героями ради заполнения экрана.

## Проход 2: весь фильм

Агент проверяет тот же план целиком: темп, чередование движения и покоя, отсутствие
однообразных импульсов, связность склеек, безопасное кадрирование, цветовую
последовательность, начало, развитие, кульминацию и финал. Исправления возвращаются
в единый план, а не в независимые планы animation/transition/color.
Структура, порядок и длительности сохраняются. Если обнаружена проблема самого
монтажа, агент оформляет предложение изменения структуры; после принятия требуется
новый hash и повторный творческий review. Не скрывать монтажную правку внутри Motion.

## Музыка и звук

Аудио не участвует в оценке сцен, определении темпа, выборе движения или переходов.
На этом этапе не генерировать музыку, не вычислять BPM и не подгонять монтаж к речи.
Новая сборка по этому маршруту должна быть визуальной sequence без вставки исходного
аудио; звук исходных файлов не удаляется. Существующий пользовательский проект
не лишается аудиодорожек без отдельного поручения: рабочая визуальная версия должна
быть отдельной sequence/копией.

`pulse_peaks` — редактируемые ориентиры на timeline для последующего подбора музыки.
Без выбранной музыки не обещать совпадения с долями или ударами. Пользователь
накладывает и подбирает музыку после визуального QA, при необходимости корректирует
пики Motion. Цель этапа — максимально законченный визуальный фильм и редактируемый
Premiere-проект. «Готов для клиента» подтверждается просмотром нативного результата,
а не полнотой JSON.

## Процедурный пакет и контракт

`scripts/creative_finish_plan.py` не запускает модель или Adobe. Он готовит
материалы для агента из уже утверждённого structure JSON и проверяет законченный
план. Агент сам просматривает визуальные материалы и принимает решения.

```powershell
python scripts/creative_finish_plan.py packet --structure <LOCAL_PATH> --output <LOCAL_PATH>
python scripts/creative_finish_plan.py check --plan <LOCAL_PATH>
```

Структура: `task_id`, `branch`, `fps`, упорядоченный `clips`; у клипа `id`,
`path`, `kind` (image/video), `frames`, опционально `timeline_start_frame`,
`source_in_seconds`, `speed`. Для видео пакет извлекает начало/середину/последний
кадр именно используемого фрагмента. Изображения остаются по постоянному пути.
Каждый source/evidence и исходная структура защищены SHA-256.
Пакет создаётся вне репозитория, без перезаписи существующего каталога.

Сцена плана содержит `observation`, `motion`, `color` и визуальные доказательства.
Пример решения:

```json
{
  "motion": {
    "mode": "pulse",
    "keys": [[0, 1, 0.5, 0.5], [0.5, 1.04, 0.5, 0.5], [1, 1, 0.5, 0.5]],
    "reason": "Мягкий акцент на общем портрете; оба лица остаются внутри кадра"
  },
  "color": {
    "mode": "preserve",
    "values": {},
    "reason": "Цвет уже согласован с соседними сценами"
  }
}
```

Ключ Motion: `[доля длительности, коэффициент масштаба, центр X, центр Y]`.
Это относительная композиция, не готовое значение Premiere Scale: исполнитель
учитывает baseline, геометрию и existing Motion. Hold требует причины; Lumetri
задаёт явные именованные параметры. Переход содержит `left`, `right`, `decision`
(cut/cross_dissolve), `frames`, `left_exit`, `right_entry`, `reason`; dissolve также
`handle_check: "REQUIRED"`. Наличие этого поля не доказывает доступность handles.

`second_pass`: `status: "ACCEPTED"`, все `reviewed_scene_ids`, все
`reviewed_boundaries` (пары ID), объяснения `rhythm`, `composition`,
`color_continuity`, пустой список `issues`. `pulse_peaks` содержит `scene_id`,
`frame` на глобальной timeline и `purpose`. Итоговый статус плана —
`PLAN_READY_NATIVE_PENDING`, а не COMPLETE. Проверка подтверждает контракт и
неизменность файлов, но не художественное качество и не фактический просмотр агентом.

## Нативное исполнение и границы текущего кода

Один принятый план может исполняться внутренними техническими операциями Motion →
переходы → Lumetri. Они не являются отдельными творческими этапами и не должны
повторно придумывать решения. Желателен один подготовленный WORK-проект и один
JSX с checkpoints, журналом и readback. Агент не запускает Adobe: пользователь
открывает копию и выполняет проверенный JSX. Экспорт только по текущему заданию.

Сейчас подготовка пакета и проверка единого плана реализованы. Прямой автоматический
перевод этого контракта в полный native executor ещё не реализован. Старый
`run_all` сохраняет прежние checkpoints; новый пакет не добавлен как его AUTO-стадия.
`family_finish_prepare.py` остаётся ограниченным исполнителем старого Motion-плана,
а `prepare_user_sequence_finish.py` — вертикальным Motion/transition preparer,
сохраняющим существующий Lumetri. Новый JSON нельзя подавать им напрямую.
Перед реальным исполнением агент должен подготовить и проверить адаптацию единого
плана к поддерживаемым механизмам, включая silent assembly и цвет.
Код планирования применим к 16:9 и 9:16; это не подтверждённая нативная поддержка
горизонтального доведения. Для каждого формата нужны собственные геометрия и QA.
