# Подготовка материалов последовательности к классификации

```bat
run_prepare_classification_input.bat config_inventory_Hero.local.json
```

Создайте конфигурацию задания по `config_inventory.example.json`. Пути в ней
разрешаются относительно файла конфигурации. `hero_config` указывает конфиг героя
с необязательными `human_detail_txt`, `family_detail_txt`, `family_screenshot`.
Для локального Ben 26 уже подготовлен `config_inventory_Ben26.local.json`;
запуск batch без аргумента использует его.

Скрипт читает сохранённый `.prproj` без Adobe, не изменяет проект, последовательности
и оригинальные медиа. Каждый запуск создаёт новую папку внутри `output_root`.
`target_sequence` сохраняется как контекст будущей сборки, но не редактируется.

## Результат и контракт следующего этапа

- `classification_input.json` — вход следующего классификатора, версия схемы 1.
  Продолжать можно только при `status: READY`; FAILED/BUILDING не пригодны.
- `inventory.json` — уникальные файлы, SHA-256, типы и все размещения с точными
  timeline/source ticks. Число ticks в секунде указано в манифесте.
- `previews/` — изображения для анализа; для видео по три кадра (10%, 50%, 90%)
  каждого использованного диапазона.
- `contact_*.jpg` — листы по 20 изображений с ID и номерами размещений видео.
- `context/` — проверенные копии описания героя и семейных материалов.

Дедупликация идёт по пути файла; одинаковое содержимое по разным путям не сливается.
ID стабилен при неизменном абсолютном пути. Оригиналы не копируются: классификатор
читает их по `path` и перед анализом должен сверять SHA-256. Для переноса пакета на
другой компьютер необходимо отдельно перенести медиа и сопоставить пути.

Обзорные кадры не показывают движение и звук целиком. Для содержательной классификации
видео следующий этап должен читать полные использованные диапазоны или запрашивать
дополнительные кадры. Эффекты Premiere, Motion и цветокоррекция в превью не запекаются.
Аудиодорожки, титры и графика не классифицируются этим этапом. Неразрешённые элементы,
включая неподдерживаемые вложенные sequence, отсутствующие медиа и ошибки превью
останавливают подготовку, а не пропускаются молча.

AI в этой подготовке не вызывается. Манифест фиксирует AI по умолчанию для будущей
классификации; классификатор реализован: `run_classify_source_package.bat`.

## Следующий batch: классификация

Скопируйте `config_classification.example.json` в личный конфиг, укажите
`input_manifest` готового пакета и `output_root` результатов.

```bat
run_classify_source_package.bat config_classification_Hero.local.json --dry-run
run_classify_source_package.bat config_classification_Hero.local.json --limit 3
run_classify_source_package.bat config_classification_Hero.local.json
```

Dry-run не вызывает API. Обычный запуск использует OpenAI Responses API,
OPENAI_API_KEY и модель из конфига; передаёт превью, текст героя/семьи и изображение
дерева. AI включён по умолчанию; API оплачивается отдельно. `ai_enabled: false`
создаёт ручные заготовки. Для видео анализируются только обзорные кадры.

Выход: JSONL, CSV, HTML и `classification_result.json`. Полный AI-результат имеет
статус CLASSIFIED_REVIEW_REQUIRED; ограниченный запуск — PARTIAL. Все решения REVIEW.
Кэш учитывает модель, инструкцию, контекст, превью, исходные хеши и диапазоны.
При повторном запуске ответы переиспользуются, результаты пишутся в новую папку.
Следующий монтажный этап пока не реализован.

## Прогресс длительной классификации

Каждый запуск, включая dry-run, сразу печатает путь к UTF-8 журналу в
`output/classification_logs/` рядом с конфигурацией. Сообщения одновременно
сохраняются в файл и выводятся в консоль с немедленным flush.

- VERIFY: номер, ID и путь проверяемого исходника.
- ITEM / START API: какой материал обрабатывается, сколько превью отправляется.
- WAIT: каждые 15 секунд во время проверки хеша или ожидания API; указано время ожидания.
- DONE: материал завершён, время, источник результата (AI, кэш или ручная заготовка), общий прогресс.
- REPORTS / FINISH: запись отчётов и итоговый статус.
- ERROR / STOP: ошибка или прерывание. Последний ITEM показывает текущий материал.

WAIT подтверждает работу локального процесса, но не доказывает продвижение
запроса на сервере. Тайм-аут API 120 секунд и до двух повторов означают, что
общее ожидание может быть дольше двух минут. Текст семейных справок, изображения,
ключ API и содержимое ответов в журнал не записываются; имена и пути файлов
локальные, поэтому журнал не предназначен для публичного GitHub.
`classification_result.json` содержит `progress_log` и текущий материал во время работы.

Классификатор запрашивает строгую JSON-схему ответа. Некорректный или неполный JSON повторяется до трёх попыток; явный отказ API не повторяется. Ошибочные ответы сохраняются локально в `diagnostics/<ID>/` папки запуска. После остановки повторите прежнюю команду: готовые карточки берутся из кэша. Диагностика может содержать персональные описания и не публикуется.

## Этап 3: формирование структуры видео

Реализованы `tools/build_video_structure.py` и `run_build_video_structure.bat`.
Конфиг: `config_structure.example.json`; личный Ben 26: `config_structure_Ben26.local.json`.
Рабочее предположение для Ben: 300 секунд, тематический рассказ. Это редактируемые
настройки, не утверждённый сценарий. `required_ids` задаёт обязательные материалы,
`excluded_ids` исключения. AI включён по умолчанию, модель задаётся явно.

```bat
run_build_video_structure.bat config_structure_Ben26.local.json --dry-run
run_build_video_structure.bat config_structure_Ben26.local.json
```

Вход — `classification_result.json` полной классификации и соседний `catalog.jsonl`.
Выход — новая папка `output/Ben26/structure/` с `structure.json`, `review.html`,
`structure_result.json`, `progress.log`. Статус DRAFT_REVIEW_REQUIRED: требуется просмотр.
Формируются смысловые блоки, порядок, отбор, причины выбора и примерная длительность.
Проверяются ID, запреты, обязательные материалы, отсутствие повторов, длительность
в пределах 10% цели и доступная длина выбранных видеодиапазонов.

Dry-run не вызывает API. Обычный запуск передаёт текст каталога и текстовые справки
OpenAI; нужны OPENAI_API_KEY и API-баланс. Кэш зависит от входа, настроек и инструкции.
Журнал сообщает ожидание каждые 15 секунд. AI off создаёт ручную заготовку MANUAL_REQUIRED.
Справочное семейное дерево не является сценой видео: в части карточек классификации
оно ошибочно смешано с описанием кадров. Инструкция структуры требует игнорировать
эту примесь; это не заменяет человеческую проверку и не исправляет исходные карточки.

Точные IN/OUT, звук, монтаж Premiere и экспорт 720p/1080p/4K здесь не выполняются.
Они относятся к последующим этапам. Проект и исходные материалы не изменяются.

При формировании структуры JSON-схема ограничивает material_id допустимым списком. Повторная попытка получает предыдущий ответ целиком и все найденные ошибки ID/повторов/длительности. Повторы не удаляются молча, длительности автоматически не растягиваются. Проверка плана остаётся обязательной.

## Этап 4: простой MP4 для просмотра

```bat
run_render_structure_draft.bat config_draft_Ben26.local.json --dry-run
run_render_structure_draft.bat config_draft_Ben26.local.json
```

Исполнитель `tools/render_structure_draft.py`; шаблон `config_draft.example.json`.
Читает структуру и каталог; проверяет хеши выбранных исходников. Сохраняет точный
`edit_plan.json`: порядок, длительности, source IN/OUT и timeline frames.
Для видео берёт начало первого по хронологии использованного диапазона достаточной
длины. Это автоматический черновой выбор, требующий просмотра движения и звука.

Каждый запуск создаёт новую папку с `draft_720p.mp4`, планом, `render_result.json`,
`progress.log`, `ffmpeg.log` и промежуточными `segments/`. Профиль Ben: 1280×720,
25 fps, H.264 около 1400 kbit/s, AAC 128 kbit/s, faststart. Размер зависит от содержания.
Без музыки, титров, декоративных эффектов; исходный звук видео сохраняется,
фотографии и немые видео получают тишину. Пропорции сохраняются с чёрными полями.

Это FFmpeg-предпросмотр, а не нативный рендер Adobe. Premiere-проект не меняется.
Полное декодирование MP4 проверяется автоматически. Перед отправкой зрителям
нужен просмотр смысла, выбранных моментов и слышимости звука. Google Drive автоматически
не загружается. Высокое разрешение — отдельный будущий профиль после исправления плана.

## Этап 5: нативная сборка и экспорт Premiere 1080p

`run_prepare_native_export.bat config_native_Ben26.local.json --dry-run` проверяет
план, хеши выбранных файлов, пустую target sequence и наличие preset.
Без `--dry-run` создаёт новую копию `.prproj`, `job.json` и `assemble_export.jsx`.
Вход Ben — точный edit_plan последнего черновика 20260916_183443_0df419d5,
13 материалов, 328 секунд. Конфиг `config_native_Ben26.local.json`, шаблон
`config_native.example.json`. Общий исполнитель `tools/prepare_native_export.py`.

Этот batch только подготавливает native-запуск. Автоматического моста batch→CEP
пока нет. Статус PREPARED_NATIVE_NOT_RUN не означает, что экспорт выполнен.
Откройте выведенную копию проекта в Premiere, затем Window → Extensions →
Run Transition Script; вставьте путь assemble_export.jsx и запустите.
Панель уже установлена на текущем компьютере. Сохраните свою текущую работу
перед переключением проекта. JSX отказывается работать с другим проектом,
непустой результирующей sequence или существующим MP4.

JSX настраивает B_26_1 на 1920×1080, 25 fps, импортирует оригиналы в отдельную
корзину, использует IN/OUT и порядок из edit_plan, масштабирует до кадра с
сохранением пропорций, сохраняет звук видео. Проверяет native тайминг,
ссылки, длительность, затем сохраняет копию и вызывает exportAsMediaDirect
с установленным YouTube 1080p HD.epr. Новая история/AI и повторный отбор не нужны.
Файл результата `native_1080p.mp4`; прогресс `native_progress.log`, статус
`native_status.txt`. EXPORT_FILE_CREATED_REQUIRES_MEDIA_QA требует дальнейшей
проверки реального MP4 и просмотра звука/кадрирования. При ошибке не запускайте
сценарий повторно в частично собранной sequence: создайте новую копию через batch.

Пока проверена подготовка и синтаксис JSX; native выполнение и экспорт не проверены.
Не обещается побайтовое/пиксельное совпадение с FFmpeg: Adobe может иначе обработать
цвет и звук. Монтажный порядок и временные диапазоны должны совпадать.
API-источник: https://github.com/Adobe-CEP/Samples/blob/master/PProPanel/jsx/PremierePro.23.0.d.ts

Исправление native JSX: при настройке разрешения сохраняются типы Time, PAR и Field из Adobe getSettings; исходная target sequence должна иметь 25 fps. В native_progress.log пишутся операции, а ошибка содержит operation и line. Ошибка Illegal Parameter type возникла до первого ASSEMBLING; конкретная строка старым журналом не фиксировалась. Новый вариант требует повторной проверки в Premiere.

Исправление native-вставки по фактическому журналу Adobe: строковая позиция overwriteClip передаётся в ticks, а не в секундах. Клип ищется по пути и позиции; перед экспортом повторно сверяются все размещения. После частично выполненного ошибочного запуска используется новая копия проекта, старую последовательность автоматически не очищаем. Нативный экспорт всё ещё требует подтверждения.
